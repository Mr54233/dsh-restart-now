## 1. 测试策略

三层递进，**严禁直接在 desktop profile 上首测**（重启会杀宿主进程）：

1. **L1 单元测试**（node，无副作用）：helper 命令拼装、Q6 围栏判定、环境判定、日志路径生成。
2. **L2 集成测试**（`dsh web` profile）：路由可达、环境门禁行为、allowRestart=false 行为；用"假 exe 路径"验证失败路径，不真重启。
3. **L3 手工端到端**（desktop profile）：真实重启全链路。

## 3. L2 集成测试（web profile）

前置：`dsh plugin --profile web add <本地包>` 装入；`curl http://127.0.0.1:<port>/` 可达。
注（Q2 定案后）：web 环境下入口隐藏、路由执行被环境门禁拒绝——L2 验证的是「口子」本身（路由注册与门禁行为），重启全链路由 L3 桌面端覆盖。

## 9. 测试执行记录（2026-10-09）

**L1 单元测试**：`npm test` **40/40 全绿**（U1–U4 helper v0.7 版、U5–U6 围栏 v0.6、U7 环境 v0.5、U8 exe 推导、U9a–U9f node 解析矩阵、U10 schema、U11a–c 派发 v0.9 wscript/VBS 版、U12a–f config-store v0.8）。执行过程记录：U1 初版因 detached powershell 静默失效重写为 node -e 断言（机制 errata，《02-实施文档》§5）；U9c 暴露并修复 `runtime\bin` 段回推多一级 dirname 的 bug；U3/U11 首跑 3 例失败均为测试自身断言写错（`}, DELAY);` 字面量、`args[4]` 索引），实现无改动；v0.9 U11a/b 重写为 wscript 断言。

**现场勘误（v0.5，2026-10-09 桌面真机安装后）**：用户装入桌面 profile 后按钮不出现——探测口实测返回 `{"environment":"web"}`。根因：M1 抄自 dshmarket 的「desktopProfiles 存在=桌面」判定在官方 v44 宿主上不成立（asar 全文零命中，该服务实为第三方壳标记）；官方桌面判定应为 `profileContext.name==='desktop'` 且非 CLI 启动（dshmarket index.ts:183-204，#702）。修复：lib/environment.js 重写为三段式判定（+argv 无 `--profile` 守卫，防 `dsh --profile desktop` 误伤用户终端），U7 扩至七例（a–g），`npm test` 25/25 全绿；web profile 副本已同步。教训：**单测全绿只能证明「实现=文档」，不能证明「文档=真相」；真机集成测试（E 系列前置探测）不可省**。

**现场勘误（v0.6，2026-10-09 桌面真机首点后，三问题）**：
1. **「重启被拒绝： untrusted」**——围栏把自家真机请求拒了。根因：桌面构建宿主前有剥请求头的内部代理（dshmarket http.ts:147-152 原注释自证 #648），Origin 被剥/改 → 首版「必须 Origin===http://$Host」全拒。修复：guard.js 重写为 inspectRequest 语义（loopback 硬条件 + Host/Origin 存在即校验 + 缺失/转发头容忍记 notes），与 dshmarket 原版两段式对齐；新增 %TEMP%\dsh-restart-now-debug.jsonl 留痕每次动作口请求。U5/U6 重写（9+2 例）。
2. **侧栏图标 tofu 方块**——⟳(U+27F3) 桌面字体缺字形。修复：内联 SVG（feather rotate-cw）。
