## 1. 背景

DSH 桌面版是 Electron 应用，架构为三层：

- Electron 主进程（`DeepSeek Harness.exe`）
- utility 子进程：运行 cordis 插件树 + Web 服务（127.0.0.1:19387）
- 渲染进程：加载该 Web UI

插件/配置变更（装插件、改 cordis.patch.yml、换模型配置等）大多需要**完整重启桌面应用**才生效。现状痛点：

1. 现有 dshmarket 插件带「立即重启」能力，但官方桌面端受限（`official-desktop.js` 明确桌面 profile 由应用内置插件管理器接管，部分场景只提示"请手动重启"）。
2. 手动重启 = 托盘退出 + 重新找图标打开，两步操作，且容易忘记正在跑的会话。

## 2. 目标

在 DSH Web UI 内提供一个**一键重启整个桌面应用**的入口：点击 → 确认 → 应用自动退出并重新拉起，无需用户碰托盘或文件管理器。

## 4. 功能需求

- **FR-1 重启入口**（已定案，M1 落定具体插槽）：双入口——
  - **侧边栏底部动作图标**（`sidebar.footer.action` 插槽，官方插槽注册表登记：kind:list、replaceRisk:'none'、ownerProps `{wide:boolean}`）：全局快捷入口；
  - **设置页区块**（`settings.section` 插槽）：正式入口。
  - 挂载前置：客户端经探测口获知环境，仅 desktop 挂载（§1.1 门禁）。
  - 已排除：账户上拉菜单（经查证无对应插槽，官方 shell 组件不可注入）、Windows 托盘（托盘归 Electron 主进程，插件所在 utility 进程无法触及）。
- **FR-2 二次确认**：点击后弹确认框，明确提示"将退出并重新启动 DeepSeek Harness；正在运行的任务会中断"。
- **FR-3 重启执行**：宿主半边收到指令后（**v0.7 机制勘误**：助手经 WMI `Win32_Process.Create` 派发，父进程 = WmiPrvSE、脱离本进程树，taskkill /T 连坐不到它；**杀树动作从宿主移交助手，单一杀手原则**；**v0.9 派发器勘误**：v0.7 的 `powershell -WindowStyle Hidden` 派发器被火绒「隐藏执行PowerShell」HIPS 规则拦截 → 改为 `wscript.exe + 静态 VBS`，全链路零 powershell）：
  1. 写助手脚本 + 静态派发 VBS 到 `%TEMP%`，`wscript.exe //B //Nologo`（GUI 子系统，自身零控制台）执行 VBS，经 WMI 拉起助手（脱离树）；
  2. 助手：延时 → `taskkill /PID <ppid> /T /F` 杀整树 → 轮询旧主进程退出（30s 上限，超时放弃绝不双开）→ 800ms 缓冲 → detached 重新拉起 `DeepSeek Harness.exe`；
  3. 全程无可见黑窗（**v0.9**：派发器 wscript 零控制台；助手经 WMI `Win32_ProcessStartup.ShowWindow=0` 以隐藏态创建控制台。现场勘误：ShowWindow=0 与 CreateFlags=CREATE_NO_WINDOW 组合被 WMI 拒绝 rc=21，只能单用 ShowWindow=0）。
- **FR-4 状态反馈**：确认后按钮进入"重启中…"态；页面断连后由浏览器自动重连（DSH 自带）。
- **FR-5 失败兜底**：助手启动失败或新实例未在超时窗口内起来时，写日志到 `%TEMP%\dsh-restart-now-<时间戳>.err.log`；下次打开页面时如有上次失败记录，展示提示。
- **FR-6 配置项**（cordis config，均可选；**v0.12 起 5 项**）：`allowRestart`（总开关，默认 true，false 时入口隐藏）、`confirm`（二次确认开关，默认 true）、`hideSidebarButton`（**v0.12 新增**：隐藏侧栏底部重启入口，默认 false=展示；保存后立即生效）、`delayMs`（应答后到杀树的延时 ms，默认 500）、`exePath`（exe 路径覆盖；**默认留空 = 按当前安装位置自动推导**，装在任何目录都成立，一般用户无需填写）。
  **v0.8 修订（配置 UI）**：真机证实宿主设置页不渲染 schemastery `Config` 导出 → 四项由插件**自绘表单**（settings.section 内），经 `GET/POST /plugins/dsh-restart-now/config` 读写配置文件 `<profile>\restart-now.config.json`（config-store.js 三层合并：代码默认 < patch 条目 config < 配置文件）。patch 条目 config 通道保留不变（I3 已实证）。

## 5. 非功能需求

- 不依赖 DSH 内部 IPC 或未公开 API 的**硬**依赖；所用公开面均已经 M1 源码级核实（HTTP 路由注册、客户端注入、插槽契约，见《02-实施文档》附录 A 6–10）。
- 幂等：重复点击不产生多个助手进程。
- 可追溯：每次重启在 %TEMP% 留 out/err 日志。
- 不修改 DSH 安装目录（D:\dsh）内任何文件；只在自己包目录 + profile 配置层工作。

## 6. 约束（调查已确认的事实）

1. 插件代码运行在 utility 子进程内，**拿不到 Electron 主进程的 `app.relaunch()`**；因此采用"detached 助手 + 杀树 + 重拉 exe"方案（dshmarket 同款思路）。
2. 官方桌面 profile 不能用 `dsh plugin --profile desktop add` 安装（被禁）；安装走 **设置 → 插件**（应用内置管理器）。
3. 重启会杀掉当前会话的宿主进程——文档与 UI 必须提示。
4. Windows 下拉起新实例需经 detached 助手（v0.4 errata：**必须用 node 进程，不能用 powershell**——DETACHED_PROCESS 下 powershell `-Command` 静默不执行，bisect 实锤，详见《02-实施文档》§5 机制 errata），并等旧主进程真正退出（否则双实例）。

## 7. 范围外（v1 不做，v1.1 规划）

- **dsh web 环境的一键重启**（v1.1：web 场景下提供 dshmarket 式宿主重启；v1 行为见附录 Q2：入口隐藏、路由仍注册但被门禁拒绝执行并提示 use dshmarket）
- 应用自更新/版本升级
- 多 profile（tui）批量管理
- macOS/Linux 适配（本机为 Windows；代码留 platform 分支但不做主路径测试）

## 8. 验收标准

1. 在桌面版 UI 点按钮 → 确认 → 应用窗口消失并在 30s 内重新出现，Web UI 自动恢复。
2. 重启后：插件仍启用、会话列表完整、端口 19387 正常服务。
3. 全程无弹出的控制台黑窗。
4. 人为制造失败（改错 exe 路径）时：%TEMP% 有 err 日志，页面重连后可见失败提示。
5. 该插件自身的装卸走「设置 → 插件」全程可用，不破坏桌面 profile。
6. 侧边栏入口为图标形态、风格与官方图标一致；插件停用后两个入口均消失。
