## 1. 总体架构

```
渲染进程(client.js 按钮)
   │ POST /plugins/dsh-restart-now/restart  (同源 fetch)
   ▼
utility 宿主进程 (lib/index.js, cordis apply(ctx))
   │ ① spawn detached PowerShell 助手:
   │    Wait-Process -Id <Electron主进程PID> ; Start-Process "D:\dsh\DeepSeek Harness.exe"
   │ ② 延时 500ms
   │ ③ taskkill /PID <ppid> /T /F   (杀整棵树, 宿主自身一起退出)
   ▼
助手(独立存活) → 等 Electron 主进程退出 → 重拉 exe → 新一轮 DSH 启动
   │
   └─ 失败时写 %TEMP%\dsh-restart-now-<stamp>.err.log
```

关键事实（已验证）：

- utility 宿主进程的 `process.ppid` = Electron 主进程 PID。
- exe 路径：**自动推导，用户无需填写**——utility 宿主进程本身就是 `DeepSeek Harness.exe`（Electron 进程树实测），故 `dirname(process.execPath)` = 当前安装目录（装在 `D:\dsh`、`C:\Apps\DSH` 还是别处都推得对），拼上 `DeepSeek Harness.exe` 即得目标。`exePath` 配置仅为逃生舱（默认留空=自动推导；仅当未来版本进程形态变化导致推导失准时的手动兜底）。
- Web 端口 19387；助手必须等旧树退出后再拉起，避免端口占用。

门禁规则（v1）：

- **入口**（侧边栏/设置页）：仅 `desktop` 挂载；`web` 下客户端不渲染入口。
- **路由**：两种环境都注册（保证可探测、可测），但 `web` 环境下执行被拒，返回 `{ok:false, reason:'non-desktop', hint:'use dshmarket'}`——**绝不在 web 环境杀 ppid**（那会杀掉用户终端的进程树）。
- **v1.1**：`web` 分支改走 dshmarket 式宿主重启（重启自身 node 调用并重拉 `dsh web`），环境判定与重启执行已分离成独立模块，届时只加不改。

## 5. lib/index.js — 宿主半边核心（路由 API 已核实：dshmarket/src/index.ts:180 + routes.ts:1720）

```js
import { spawn } from 'node:child_process';
import { writeFileSync, existsSync } from 'node:fs';
import { join, dirname } from 'node:path';
import { tmpdir } from 'node:os';
import { buildHelperScript, buildHelperSpawn, resolveExe, resolveNodeExecutable } from './helper-src.js';
import { detectEnvironment } from './environment.js';
import { isTrustedRequest } from './guard.js';

export const name = 'dsh-restart-now';

// 路由 handler = RAW node http：(request: IncomingMessage, response: ServerResponse) => void|Promise<void>
// webServer.register 返回注销函数（disposer），注册表见 routes.ts:1720 收集模式
export function apply(ctx, config = {}) {
  ctx.inject(['webServer'], (host) => {
    const registrations = [
      // 探测口（GET）：客户端启动时据此决定是否挂载入口（§6）
      host.webServer.register({
        kind: 'exact',
        path: '/plugins/dsh-restart-now/environment',
        handler: (req, res) => {
          if (req.method !== 'GET') { res.writeHead(405, { allow: 'GET' }); return res.end(); }
          return sendJson(res, 200, { ok: true, environment: detectEnvironment(ctx) });
        },
      }),
      // 动作口（POST）
      host.webServer.register({
        kind: 'exact',
        path: '/plugins/dsh-restart-now/restart',
        handler: (req, res) => handleRestart(req, res, ctx, config),
      }),
    ];
    ctx.on('dispose', () => registrations.forEach((d) => d()));
  });
}

function handleRestart(req, res, ctx, config) {
  if (req.method !== 'POST') { res.writeHead(405, { allow: 'POST' }); return res.end(); }

  // 门禁顺序（v0.2 定案）：① allowRestart → ② environment → ③ Q6 围栏
  if (config.allowRestart === false) return sendJson(res, 403, { ok: false, reason: 'disabled' });

  const env = detectEnvironment(ctx);
  if (env !== 'desktop') {
    // 绝不在 web 环境杀 ppid（那是用户终端的进程树）
    return sendJson(res, 403, { ok: false, reason: 'non-desktop', hint: 'use dshmarket' });
  }
  const fence = inspectRequest(req);
  if (!fence.trusted) {
    // Q6（v0.6 修订语义）：loopback 对端硬条件 + Host/Origin 存在即校验；
    // 缺失/转发头容忍（桌面构建剥头代理 #648），全部留痕 debug 日志
    return sendJson(res, 403, { ok: false, reason: 'untrusted' });
  }

  const stamp = new Date().toISOString().replace(/[:.]/g, '-').slice(0, 19);
  const errLog = join(tmpdir(), `dsh-restart-now-${stamp}.err.log`);

  // exe 自动推导（§1）；推导结果不存在时 fail-fast，不 spawn 助手
  const exe = resolveExe(config, process.execPath);
  if (!existsSync(exe)) {
    writeFileSync(errLog, `exe not found: ${exe}`);
    return sendJson(res, 500, { ok: false, reason: 'exe-not-found', errLog });
  }

  const ppid = process.ppid;
  // 助手 = detached `node -e <script>`（机制 errata 见下：detached powershell 静默失效）
  const script = buildHelperScript(exe, ppid, { errLog, delayMs: config.delayMs ?? 500 });
  const cmd = buildHelperSpawn(resolveNodeExecutable(), script);
  try {
    const helper = spawn(cmd.file, cmd.args, cmd.options);
    helper.on('error', (e) => writeFileSync(errLog, String(e?.stack ?? e)));
    helper.unref();
  } catch (e) {
    writeFileSync(errLog, String(e?.stack ?? e));
    return sendJson(res, 500, { ok: false, reason: 'helper-spawn-failed', errLog });
  }
  // 应答后延时杀树；taskkill /T 连同宿主自身一起退出
  setTimeout(() => {
    spawn('taskkill', ['/PID', String(ppid), '/T', '/F'], { stdio: 'ignore', windowsHide: true });
  }, config.delayMs ?? 500);
  return sendJson(res, 202, { ok: true, boot: stamp });
}

function sendJson(res, status, payload) {
  res.writeHead(status, { 'content-type': 'application/json' });
  res.end(JSON.stringify(payload));
}
```

### 机制 errata（v0.4，实测实锤）

原设计「detached powershell -NoProfile -WindowStyle Hidden -Command <script>」在集成测试 I5 中**静默失效**：`.m4/i5-bisect.cjs` 矩阵证明 `detached: true`（DETACHED_PROCESS）下 powershell.exe `-Command` **不执行脚本**（exit 0、无输出、无副作用），含/不含 windowsHide 均如此；`windowsHide` 单独使用正常；`shell:true`+detached 可跑但引入 cmd 引号脆弱性。而 **node 进程 detached 下正常运行**（node 无控制台依赖）——dshmarket 的 detached 助手正是 `node -e`（restart.ts:582-588，`{detached, stdio:'ignore'} + unref`）。

随之变化的还有三点：

- node 解析：桌面宿主 utility 进程的 `process.execPath` 是 Electron exe 而非 node，故新增 `resolveNodeExecutable()`（argv 扫描 → `primary-runtime\dependencies\node\bin\node.exe`，v44.0.0 实测存在，node 24.21.0）；
- 超时语义收紧：助手轮询 ppid 30s 仍存活（taskkill 未生效）时**放弃重启并留痕**（`wait ppid timeout`），绝不拉起第二实例；
- 单测 U1–U4 重写为 node 脚本断言，新增 U9a–U9f（resolveNodeExecutable 优先级矩阵）；`npm test` 20/20 全绿，I5 复跑 PASS（errLog 落痕 `Start-Process failed: … ENOENT`）。

设计对齐点（承 dshmarket/lib/restart.js 实测源码）：

- 助手 `detached: true` + `stdio:'ignore'` + `unref()`，先等 ppid 退出再拉起；
- 失败必须留痕到 %TEMP%（dshmarket #177 教训：静默失败 = "按钮点了没反应"）；
- 端口释放等待：本 v1 用固定 800ms 缓冲；若实测出现 EADDRINUSE，升级为 dshmarket 式端口探测循环（net.connect，30s 上限）。

### 机制 errata v0.7（E1 真机失败实锤：WMI 逃逸树 + 单一杀手）

**失败现场**（v0.6 真机首点，2026-10-09）：确认框点确定 → 窗口直接消失、**没有重启回来**，用户手动拉起。%TEMP% 仅有 debug 日志（围栏 verdict=trusted，v0.6 修复已生效）、**无任何 .err.log**、无残留助手进程。

**根因**：v0.6 宿主流程 = spawn detached node 助手 → 宿主自己 `setTimeout(delayMs)` 后 `taskkill /PID ppid /T /F`。**`/T` 按父子关系遍历杀树**——detached 只断控制台关系，**不断 Windows 父子关系**，助手仍是 utility 宿主的子进程 → 助手被连坐杀死，没来得及等旧进程退出、更没拉起 exe；errLog 无内容（被杀非报错）。dshmarket 不踩此坑因为它 `process.exit()`/SIGTERM 只杀**单进程**不杀树。

**v0.7 修复（WMI 逃逸树）**：

1. 宿主把助手脚本写到 `%TEMP%\dsh-restart-now-helper-<stamp>.cjs`（不再 `-e` 内联）；
2. 派发器 = `powershell.exe -NoProfile -WindowStyle Hidden -Command "Invoke-CimMethod Win32_Process Create CommandLine='\"node\" \"helper.cjs\"'"`——派发器本身在树内但 WMI Create 很快返回即退出；**助手的父进程 = WmiPrvSE，不在目标树内**，taskkill /T 连坐不到它；
3. **单一杀手原则**：杀树动作整体移交助手（宿主删除 setTimeout taskkill）。助手职责：延时 → `taskkill /PID ppid /T /F` → 轮询 ppid 死亡（30s 上限，EPERM 视为存活；**超时放弃绝不双开**）→ 800ms 缓冲 → detached 拉起 exe（失败写 `Start-Process failed`）；
4. WMI 失败写 errLog（`WMI create failed: <ReturnValue>` / `WMI invoke failed: ...`），**应用保持存活可重试 = 安全失败方向**；
5. 约束：WMI Create 无法设置环境变量 → ELECTRON_RUN_AS_NODE shim 方案（U9d）在 WMI 路径不可用 → `isStandaloneNode(nodeExec)` 守卫，非独立 node → 500 `helper-dispatch-unavailable`（桌面场景 argv 扫描命中 primary-runtime 真 node，v44 实测存在）。

**验证**（`.m4/i5-v07.cjs`）：A) marker 助手经 WMI 派发后父进程实测 = `WmiPrvSE.exe`（逃逸树成立）；B) 假 exe 助手亲手 taskkill 祭品进程 → errLog 落痕 `Start-Process failed: … ENOENT`。`npm test` U1/U3 重写 + 新增 U11a–c，**40/40 全绿**。

### 机制 errata v0.9（E1 真机成功但火绒拦截 + 黑框：wscript+VBS 派发）

**真机现场**（2026-10-09 11:15/11:20，E1 首次真重启）：第一次点击被火绒「系统加固」拦截（发起程序 DeepSeek Harness.exe，防护项目「隐藏执行PowerShell」，目标 powershell.exe）；用户放行后重启成功（旧进程树 11:20:58 消失、新树起来，窗口消失约 9s 后回来）——**v0.7 机制链路本身验证通过**，但派发器 `powershell -WindowStyle Hidden` 正中火绒 HIPS「隐藏执行PowerShell」规则（Electron 应用隐藏拉起 powershell = 典型恶意行为特征），且 WMI Create 默认给助手 node.exe 开**可见黑框**（用户截图，活约 9s）。

**v0.9 修复（helper-src.js `buildDispatcherVbs` + `buildVbsDispatch`，全链路零 powershell）**：

1. 派发器 = `wscript.exe //B //Nologo <dispatch.vbs> <node> <helper.cjs> <errLog>`——wscript 是 **GUI 子系统**可执行，自身永不创建控制台（零黑框、零火绒规则命中）；`//B` 批模式脚本错误不弹窗；
2. VBS 为**静态纯 ASCII 源码**（路径一律经 wscript 位置参数传入，VBS 文件本身零路径 → 无编码问题），动作：`Win32_ProcessStartup.SpawnInstance_` 设 `ShowWindow = 0`（SW_HIDE）→ `Win32_Process.Create("""node"" ""helper""", Null, startup, pid)`；
3. **现场勘误（矩阵实测）**：`ShowWindow=0` 与 `CreateFlags=134217728(CREATE_NO_WINDOW)` **各自单独 rc=0，组合被 WMI 拒绝（Win32_Process.Create 返回 21 无效参数）**——只设 ShowWindow=0，SW_HIDE 经 STARTF_USESHOWWINDOW 让控制台以隐藏态创建，黑框消除；
4. 失败留痕同 v0.7：`WMI get failed` / `WMI create failed: <rc>` 写 errLog（VBS 内 `On Error Resume Next` + FSO OpenTextFile append）；**应用保持存活可重试 = 安全失败方向**；
5. 助手职责链不变（v0.7 单一杀手）：延时 → taskkill /T /F → 轮询 ppid 死亡 30s → 800ms → detached 拉起 exe。

## 6. lib/client.js — 浏览器半边（已核实：__ModuleLoader__ 包装 + 官方插槽）

客户端模块格式（dshmarket/client/client.js 首尾实测）：页面以 `window.__ModuleLoader__.load({id, factory})` 加载，factory 收到 `require`（可解析 react 与 dsh-client-* 外部模块），返回 module.exports；导出契约 `{name, inject, apply}`（thinking-effort client.js:9270-9272）。

```js
window.__ModuleLoader__.load({
  id: 'dsh-restart-now',
  factory: (require) => {
    const React = require('react');

    const module = { exports: {} };
    const exports = module.exports;

    // 环境门禁（§1.1 /《01-需求文档》Q2 定案）：v1 仅 desktop 挂载入口。
    // 客户端通过宿主探测口（GET /plugins/dsh-restart-now/environment，§5）获知环境，
    // 再决定是否注册插槽 —— 探测失败按非桌面处理，不挂载。
    exports.name = 'dsh-restart-now';
    exports.inject = ['slots'];
    exports.apply = function apply(ctx) {
      fetch('/plugins/dsh-restart-now/environment').then((r) => r.json()).then((info) => {
        if (!info?.ok || info.environment !== 'desktop') return;   // web：不渲染入口（v1.1 再加提示）
        const slots = ctx.get('slots');
        if (slots === undefined) return;

        // 入口一：sidebar.footer.action —— 官方预留动作位（侧边栏底部、设置旁）
        // 官方文档（app.asar 插槽注册表）：kind:list, scope:root,
        // registerOptions: id(必填)/order(可选)/label(可选 string|()=>string)
        // ownerProps: { wide:boolean }（false = 56px 窄栏）; replaceRisk:'none'
        slots.inject('sidebar.footer.action', () => slots.register(
          { name: 'sidebar.footer.action', id: 'dsh-restart-now', order: 100, label: '重启应用' },
          (props) => React.createElement(RestartAction, props),   // props 含 { wide }
        ));

        // 入口二：settings.section —— 设置页区块（确认/说明）
        // v0.6 勘误：设置页导航行 = {id, order, label: resolveSlotLabel(label)}
        // （asar:478663-478668），label 缺失 → 导航项无名字（真机「项目没有名字」根因）
        slots.inject('settings.section', () => slots.register(
          { name: 'settings.section', id: 'dsh-restart-now', order: 900, label: '重启应用' },
          () => React.createElement(RestartSection),
        ));
      }).catch(() => { /* 探测失败 = 不挂载，页面不留下死按钮 */ });
    };

    function RestartAction({ wide }) {
      // 图标钮：点击 → 确认框（config.confirm，Q3 定案）→ POST → 页面断连属预期
    }
    function RestartSection() { /* 区块说明 + 重启按钮 */ }

    async function restart() {
      // v0.6 勘误：不手动设置 origin 头——fetch 里 origin 是 forbidden header，
      // 浏览器静默丢弃；同源 fetch 自动带 Host/Origin（或被桌面代理剥掉，服务端已容忍）
      try { await fetch('/plugins/dsh-restart-now/restart', { method: 'POST' }); }
      catch { /* 页面即将断连，属预期 */ }
    }

    return module.exports;
  },
});
```

要点：

- `require('react')` 由页面加载器解析（**M4 已验证可解析**：headless Chrome 实测工厂未抛异常、无 failed 覆盖层）；
- 两个插槽均为官方文档登记的安全插槽（replaceRisk:'none'），无全局侵入；
- 挂载前置探测：探测口不可达/非 desktop 时**零入口**，不留死按钮。

**加载机制（M4 实测补充）**：客户端 JS 不走 `/plugins/<name>/client.js` 单文件路径（404 属正常）。宿主在 index HTML `<head>` 注入 **combo URL**：`plugins/??<pkg1>/client.js,<pkg2>/client.js,...&rev=<hash>`，把全部激活插件（含本插件）的 client.js 拼成一个大响应一次性服务；每个模块必须经 `__ModuleLoader__.load({id,...})` 注册（未注册会被记入 failures：`loaded without registering "<id>"`）。rev 校验整个列表，手工单条请求 404。
